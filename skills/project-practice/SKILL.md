# 实战题卡练习

## 挑题

1. `mission_list`（可按档位 `small` / `medium` / `large` 过滤）列出题卡。
2. 按用户的水平、可用时间推荐 1~3 张，说明理由（预估耗时、难度、能练到什么）。

## 开题

1. `mission_get(slug)` 读题卡：背景、需求、约束、验收标准、前置文章。
2. 前置文章用 `knowledge_get` 读取，先补知识再动手。
3. 帮用户把需求拆成可执行的步骤清单，**不要直接替用户写完整实现**，除非用户明确要求。

## 验收

1. 读用户的代码（当前仓库或用户贴的内容）。
2. 逐条对照 `acceptanceCriteria`：每条给 ✅ 通过 / ⚠️ 部分 / ❌ 未通过，并附证据（文件:行号或运行结果）。
3. 汇总：通过率、最该先改的 3 处、可以加分的地方。

## 点数与报错

工具返回「Journey 点数不足」时：停止后续调用，把报错里的剩余点数、充值链接和价格原样告诉用户，说明充值到账后直接重试即可（Key 不用换）。不要反复重试，也不要换别的工具绕过。

工具结果末尾出现「【Journey 提示】」（点数快用完）时，在回答末尾原样转告用户一次，之后不要重复。

调用报 API Key 相关错误（没读到 Key、格式不对、不存在、已吊销）时，按 `getting-started` 里的排查表把修法告诉用户，不要反复重试。
